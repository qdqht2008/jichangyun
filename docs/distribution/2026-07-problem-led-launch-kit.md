## 活动一：订阅更新失败

### 内容目的与目标读者

帮助看到 timeout、network error、401/403、parse 或 config validation 的用户先判断错误发生在哪一段，避免一上来大改配置。

### 三个标题

1. 搜索式：Clash 订阅更新失败，401/403 和解析错误怎么排查？
2. 症状式：订阅拉不下来，还是下载后读不懂？先分清这两种情况
3. 方法式：用一个分支表定位 Clash 订阅下载、鉴权与解析问题

### 社区短文

Clash 提示订阅更新失败时，先别急着删配置。第一步只判断一件事：是“下载失败”，还是“下载后无法解析”。timeout、network error、401/403 通常说明请求、网络或授权方向需要核对；但不能仅凭状态码判断具体根因，应回到商家后台确认账号状态和官方订阅链接。parse、config validation 则表示内容已经返回，但客户端没有接受。接着换一个网络形成对照，再核对客户端兼容性。不要一开始同时删除配置或修改 DNS；无法确认账号或服务端状态时就停止修改，把脱敏错误信息交给服务商支持。完整分支表：

### 短摘要

订阅更新失败先区分下载、鉴权和解析问题。按账号、官方链接、当前网络、客户端兼容的顺序逐项验证，不要同时改多个变量。

## 活动二：已连接但无法上网

### 内容目的与目标读者

帮助客户端显示已连接、但浏览器或其他应用仍无法访问网络的用户，用可回退的顺序定位接管环节。

### 三个标题

1. 搜索式：Clash 显示已连接但无法上网，系统代理、TUN、DNS 怎么查？
2. 症状式：节点显示已连接，网页却打不开，问题可能不在节点
3. 方法式：一次只改一个变量，定位 Clash 流量没有进入代理的环节

### 社区短文

Clash 的“已连接”只说明客户端或节点处于某种连接状态；已连接不等于应用流量已经进入代理。先切换一个节点，观察同一浏览器的结果。没有变化时，确认当前到底使用系统代理还是 TUN，并记录原状态。只有节点与接管方式形成清楚对照后，再检查 DNS。还可以换手机热点对比当前 Wi-Fi，但手机热点只用于形成网络路径对照，不能单独证明运营商或服务端故障。一次只改一个变量，每次改动都保留回退路径；如果日志涉及不熟悉的权限或配置字段，就停止修改并查客户端官方文档。完整步骤：

https://www.jichangyun.top/guide/connected-but-no-internet/

- **5–15 秒｜口播：** “已连接不等于应用流量已经进入代理。” **画面：** 应用 → 系统代理或 TUN → 节点的路径图。
- **15–45 秒｜口播：** “先切换节点，再确认系统代理或 TUN 的原状态；前两项形成对照后才看 DNS。需要判断本地网络时，用手机热点做一次对比。” **画面：** 节点 → 接管方式 → DNS → 热点逐步高亮。
- **45–60 秒｜口播：** “一次只改一个变量，结果不清楚就回退。遇到权限或陌生配置时停止修改，完整排查表在简介。” **画面：** 回退按钮与指南页面标题。

### 短摘要

“已连接”不代表流量已经正确进入代理。按节点、系统代理或 TUN、DNS、本地网络的顺序形成对照，每次只改变一个条件。

## 活动三：线路怎么选

### 内容目的与目标读者

### 三个标题

1. 搜索式：机场直连、公网中转、IEPL/IPLC 有什么区别？
2. 症状式：同一种线路标签，为什么不同网络下感受会不一样？
3. 方法式：把网络拆成三段，再判断直连、中转和 IEPL/IPLC

### 社区短文

选线路前，先把数据路径拆成三段：本地与接入段、运营商与跨网段、落地与目标段。直连、公网中转、IEPL/IPLC 这些标签只能作为提问起点，不能证明用户全链路，也不能替你回答实际表现。购买前应追问入口位置、节点地区、倍率、设备与退款规则，以及标签覆盖哪一段。比较时固定设备、客户端、本地网络和目标服务，一次只改一个变量；如果结果与预期不符，就停止修改，回到原配置和商家说明重新核对。三段链路图与核验表：
