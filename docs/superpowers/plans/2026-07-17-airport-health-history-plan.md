# 机场官网健康度历史评分实施计划

**目标：** 为机场官网监测新增可审计的历史事实源，让累计不足 90 天时的全部样本平均、达到 90 天后的滚动平均实际进入榜单评分与排序。

**设计依据：** `docs/superpowers/specs/2026-07-17-airport-health-history-design.md`

**架构：** `data/airport-health-history.json` 保存不可自动清理的监测样本；`js/airport-data.mjs` 负责确定性校验、窗口选择与评分合并；`scripts/check-airport-health.mjs` 在显式 `--write` 时追加历史并刷新主数据中的最新状态和派生平均分；现有榜单与机场报告继续消费共享加载结果。

---

## Task 1：用测试锁定历史数据契约与评分意图（RED）

**修改：** `tests/airport-features.test.mjs`、`tests/check-airport-health.test.mjs`

1. 增加历史文件顶层版本、记录字段、已知 slug、时间、分数范围和重复标识校验测试。
2. 锁定累计不足 90 天时使用全部样本。
3. 锁定历史跨度达到 90 天后使用以最新监测为终点、包含边界日的最近 90 天样本。
4. 锁定输入顺序不影响结果、同日多次监测分别计数、完整失败的 0 分参与平均。
5. 锁定单机场无历史记录时只回退该机场当前值。
6. 锁定历史平均分进入现有总分和同风险组排序。
7. 先运行目标测试，确认因功能缺失而失败。

## Task 2：实现历史数据纯函数与共享加载（GREEN）

**修改：** `js/airport-data.mjs`

1. 定义历史版本和 90 天窗口常量。
2. 实现历史记录校验，错误信息明确定位记录与字段。
3. 实现按 slug 分组、按时间排序和历史统计函数。
4. 平均分四舍五入到一位小数，返回分数、样本数、起止时间和 `cumulative`/`rolling` 模式。
5. 实现机场记录与历史统计合并；有历史时覆盖派生的官网健康度和最新官网状态，无历史时保留当前值并返回空统计。
6. 扩展共享加载函数并行读取两个 JSON；历史文件整体失败时显式失败。
7. 运行 Task 1 测试直至通过。

## Task 3：扩展监测脚本的追加与写入行为（RED → GREEN）

**修改：** `scripts/check-airport-health.mjs`、`tests/check-airport-health.test.mjs`

1. 先增加“追加保留旧记录”“拒绝重复标识”“非写入模式不修改文件”和“派生平均同步更新”测试。
2. 将本轮健康结果转换为历史样本，不复制人工评分字段。
3. 追加前校验现有历史和本轮样本；完全相同的 `slug + checkedAt` 显式失败。
4. 使用追加后的历史重新计算每个机场的官网健康度平均分与评分依据。
5. 使用同目录临时文件写入完整 JSON，再替换目标文件；失败以非零状态退出并指出阶段。
6. 保留不带 `--write` 时只输出结果的既有语义。
7. 运行脚本目标测试直至通过。
