# 榜单、机场报告、风险监测与检测工具设计

## 背景

当前项目是无需构建步骤的静态网站，已经包含机场推荐、机场详情、教程和故障排查内容。本次工作参考 `https://gate-rank.com/` 的公开功能组织方式，但不复制其品牌、文案、受版权保护素材、机场数据库或私有评分数据。

目标是在保留现有网站架构、URL、视觉品牌和内容资产的前提下，为当前网站已有机场增加以下能力：

- 综合榜单与多条件筛选；
- 结构化机场报告；
- 风险监测页；
- 当前出口地区与流媒体基础可达性检测工具。

## 已确认范围

### 包含

- 仅收录当前网站已有机场；
- 使用本地静态 JSON 维护机场事实、人工证据值和风险事件；
- 使用维护脚本按需检查公开官网可达性、HTTPS 与响应时间，并把带时间戳的结果写入静态数据；
- 使用确定性 JavaScript 计算编辑评分、排序和筛选结果；
- 原地增强现有 `/jichang/*/` 机场详情页；
- 增加 `/rankings/`、`/risk-monitor/` 和 `/tools/streaming-check/`；
- 仅为检测工具增加无状态 Vercel Serverless API；
- 保留当前暖色主题、衬线标题和内容站风格。

### 不包含

- 导入 GateRank 的机场条目、评分或文案；
- 节点测速、每日自动抓取、持续可用率监测或自动风险判定；
- 用户注册、登录、充值、支付、机场申请或管理后台；
- 声称检测工具能验证账号登录、完整片库或实际播放；
- 将人工资料包装成实时监测数据。

## 设计原则

1. **单一事实源**：机场事实只在 JSON 中维护一次，榜单、详情和风险页共同读取。
2. **透明评分**：公开评分维度、权重、更新时间和人工证据属性。
3. **风险优先**：风险级别是排序门槛，不能被价格或易用性平均掉。
4. **显式未知**：缺失值显示“未核对”，不猜测、不自动填零。
5. **渐进增强**：保留现有 HTML 内容；JavaScript 或数据失败时给出明确提示，不破坏原有阅读路径。
6. **能力诚实**：检测结果只描述地区推断与基础资源可达性，并解释浏览器限制。

## 架构

### 静态数据层

新增两个数据文件：

- `data/airports.json`：机场身份、价格、能力、评分输入、风险摘要和核对日期；
- `data/risk-events.json`：风险事件、证据、发生或发现日期、级别和处理建议。

新增 `scripts/check-airport-health.mjs` 作为编辑维护工具。脚本读取机场官网地址，对每个地址执行三次带超时的公开 HTTP(S) 请求，记录可达性、最终地址、状态码、HTTPS 证书有效期、响应时间中位数、检查时间和执行环境说明。脚本只在编辑人员主动运行时更新数据，不作为生产站点的定时后台。

共享 JavaScript 模块负责：

- 加载并校验 JSON；
- 计算编辑评分；
- 根据风险级别和总分排序；
- 执行搜索与组合筛选；
- 渲染统一的评分、状态、空状态和错误状态组件。

### 页面消费者

- `/rankings/` 使用共享数据渲染完整榜单和筛选器；
- `/risk-monitor/` 使用同一机场数据与风险事件数据，按风险级别展示证据；
- 现有 `/jichang/*/` 页面通过页面 slug 读取对应机场记录，增加评分、风险和能力摘要；
- `/tools/streaming-check/` 调用检测 API，并在浏览器中执行基础资源探测。

### 检测 API

Vercel Serverless API 只读取 Vercel 或代理提供的请求头，识别当前出口 IP 和国家/地区。接口不调用第三方 IP 数据服务，不写数据库，不保存检测历史，也不在应用日志中主动输出 IP。

浏览器根据 API 返回的国家/地区，结合带更新时间的服务覆盖规则，给出“官方地区支持”或“官方地区不支持”的推断；同时使用图片资源请求探测服务基础资源是否可达。二者分开展示，不互相冒充。

## 页面与导航

### 顶部导航

在现有导航中增加：

- `机场榜` → `/rankings/`；
- `检测工具` → `/tools/streaming-check/`。

保留现有 `机场推荐` 入口及其他导航项。移动端沿用项目现有响应式导航规则，不建立第二套导航体系。

### 综合榜单 `/rankings/`

页面包含：

- 标题、资料核对日期和编辑评分说明；
- 按风险优先规则排序的机场列表；
- 关键词搜索；
- 状态、价格区间、是否试用、支持客户端和流媒体能力筛选；
- 当前筛选摘要、结果数量和一键清除；
- 无结果与数据加载失败状态；
- 指向现有机场详情页和官网的明确入口。

筛选在浏览器内完成，不生成大量薄内容筛选 URL。本期不增加 GateRank 的支付、线路和国家地区长尾排行页面。

### 风险监测 `/risk-monitor/`

页面按“正常、观察、高风险”分组，展示：

- 当前风险级别；
- 风险证据或正常依据；
- 事件日期和最近核对日期；
- 建议动作，例如短周期尝试、暂停购买或等待复核；
- 指向机场报告的入口。

风险状态由人工维护，不从编辑总分自动反推。

### 机场报告 `/jichang/*/`

保留现有 URL、套餐内容、教程链接、官方入口和页面主结构，新增：

- 编辑总分与四维拆解；
- 风险状态、证据摘要和核对日期；
- 最低月付、试用、支持客户端、流媒体和节点地区摘要；
- 适用场景与选择注意事项；
- 返回综合榜单和风险页的入口；
- 说明分数属于编辑评分，不是实时测速或用户评分。

### 检测工具 `/tools/streaming-check/`

检测流程：

1. 用户主动点击“开始检测”；
2. 浏览器调用无状态 API 获取当前出口 IP/地区信息；
3. 浏览器并行探测 ChatGPT、Netflix、Claude、TikTok、Disney+ 和 HBO Max 的基础资源；
4. 页面分别展示地区覆盖推断和资源可达状态；
5. 页面明确提示结果不能证明账号登录、完整片库或实际播放成功。

检测结果不生成公开分享链接，也不写入本地或服务端历史。

## 数据模型

每个机场记录包含以下字段组：

### `identity`

- `slug`：与现有详情目录一致；
- `name`：机场显示名称；
- `detailUrl`：现有站内详情地址；
- `website`：当前核对的官网或邀请地址。

### `pricing`

- `monthlyFrom`：最低月付价格，未知时为 `null`；
- `hasTrial`：`true`、`false` 或 `null`；
- `billingCycles`：已核对的套餐周期数组。

### `capabilities`

- `clients`：支持客户端数组；
- `streaming`：公开资料中已核对的流媒体或 AI 服务数组；
- `payments`：已核对支付方式数组；
- `regions`：已核对节点地区数组。

### `scoreInputs`

- `websiteHealth`：0–100，由最近一次公开官网检查结果确定；
- `value`：0–100；
- `usability`：0–100；
- `riskSafety`：0–100。

每项输入都必须有对应人工依据和核对日期。若没有足够依据，该机场显示“评分资料不足”，不计算总分。

### `health`

- `reachable`：最近一次检查是否成功访问公开官网；
- `finalUrl`：重定向后的最终地址；
- `httpStatus`：最终 HTTP 状态码；
- `medianResponseMs`：三次请求的响应时间中位数；
- `tlsValidUntil`：HTTPS 证书有效期，无法核对时为 `null`；
- `checkedAt`：检查时间；
- `runner`：执行环境说明，用于提示结果具有地域和时点限制。

官网健康度只评价公开入口在该次检查中的状态，不代表代理节点、线路、晚高峰、下载速度或流媒体解锁能力。

### `risk`

- `level`：`normal`、`watch` 或 `high`；
- `summary`：简短事实摘要；
- `evidence`：证据条目数组；
- `reviewedAt`：最近人工核对日期。

### `metadata`

- `sources`：资料来源说明，不复制第三方正文；
- `reviewedAt`：机场整条记录最近核对日期。

## 评分与排序

编辑总分使用固定公式：

```text
总分 = 官网健康度 × 35% + 性价比 × 25% + 易用性 × 20% + 风险安全度 × 20%
```

展示分数按统一规则保留一位小数。路由、重试、字段转换和总分计算全部由确定性代码完成，不调用模型。

官网健康度使用公开规则计算：可达性占 50 分；HTTPS 证书有效占 30 分；三次请求中位响应时间占 20 分，其中不高于 1 秒为 20 分、不高于 2 秒为 15 分、不高于 4 秒为 10 分、高于 4 秒为 5 分。无法访问时该项为 0 分。页面必须同时展示检查时间和执行环境，避免把单次官网响应解释为长期稳定性。

排序分两步：

1. 先按风险级别排序：`normal` → `watch` → `high`；
2. 同一风险组内按编辑总分降序；总分相同则按名称进行稳定排序。

高风险机场无论价格、易用性或总分多高，都不能排在正常或观察机场之前。

## 视觉设计

采用已确认的“延续现有品牌”方向：

- 继续使用 `css/main.css` 中的背景、文字、边框和三种强调色变量；
- 继续使用 DM Serif Display、Inter 和 Noto Sans SC；
- 榜单卡片、筛选器和指标块使用现有圆角、边框和轻阴影语言；
- 风险颜色只作为状态提示，不覆盖全站暖色品牌；
- 数据密度适度提高，但不改造成 GateRank 风格的黑白仪表盘；
- 新增组件遵循现有桌面与移动端断点，不引入新的 CSS 框架。

## 错误处理

### 数据加载

- JSON 请求失败或结构校验失败时，页面显示明确错误提示并停止数据组件渲染；
- 不展示部分加载、字段错位或默认零分的榜单；
- 机场详情页原有静态正文继续可读；
- 缺失字段显示“未核对”。

### 筛选

- 无匹配结果时显示当前筛选摘要；
- 提供“清除筛选”按钮；
- 不把无结果误报成数据加载失败。

### 检测工具

- API 和单项资源探测超时均为 8 秒；
- API 失败时显示“网络信息识别失败”，不伪造地区结果；
- 单项资源失败不取消其他探测结果；
- 浏览器跨域、反机器人或资源策略导致的失败显示“浏览器限制”，不显示“服务不可用”；
- API 响应设置 `Cache-Control: no-store`。

## 测试与验收

### 自动测试

扩展现有 Node 测试，覆盖：

- JSON 必填字段、枚举和 slug/详情 URL 一致性；
- 官网检查脚本的三次请求、中位数、超时、重定向和证书字段；
- 四维评分公式、精度和评分资料不足分支；
- 风险分组门槛，确保高风险不能被高总分抬升；
- 总分相同的稳定排序；
- 搜索与多条件组合筛选；
- 无结果与清除筛选行为；
- 新导航链接和页面 canonical；
- API 请求方法、正常与缺失请求头、超时语义和 `no-store`；
- 当前现有页面、外链统计和 SEO 审计继续通过。

测试名称需要体现业务意图，例如“高风险机场不能因低价排到正常机场之前”，而不是只描述函数返回值。

### 浏览器验收

使用本地静态服务器验证桌面端和移动端：

- 新导航入口可达且当前项状态正确；
- 榜单首次加载、搜索、组合筛选、清除和空状态；
- 每个榜单条目能进入正确的现有详情页；
- 详情页数据与榜单一致；
- 风险页分组和证据日期正确；
- 检测工具的开始、加载、成功、部分失败、API 失败和超时状态；
- JavaScript 控制台无未处理异常；
- 现有核心页面没有布局或导航回归。

### 完成标准

只有在以下条件全部满足后才能宣称完成：

1. 所有已确认页面和功能已实现；
2. JSON 数据覆盖当前网站所有机场详情页；
3. 自动测试全部运行且通过，没有静默跳过；
4. 桌面端和移动端浏览器验收完成；
5. 失败项、受浏览器限制项和未核对数据均已显式标注；
6. 未修改与本功能无关的现有内容。

## 实施顺序建议

1. 建立并测试官网健康度维护脚本；
2. 建立并校验静态数据模型；
3. 实现确定性评分、排序和筛选模块及测试；
4. 建立榜单页和导航入口；
5. 建立风险页；
6. 原地增强现有机场详情页；
7. 实现无状态检测 API 和检测页面；
8. 执行全站自动测试与浏览器回归。
