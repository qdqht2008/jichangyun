# P1 客户端教程更新设计

**日期：** 2026-07-04
**状态：** 已确认，待实施计划
**范围：** Clash Verge Rev、FlClash、Clash Meta for Android 与教程聚合页

## 1. 背景

现有客户端教程能够覆盖基本下载和订阅导入，但存在四类影响搜索信任与用户成功率的问题：

1. 活跃客户端页面固定写死旧版本号。Clash Verge Rev 仍为 v2.4.7，FlClash 仍为 v0.8.92，Clash Meta for Android 仍为 v2.11.24。
2. 页面把第三方下载镜像标为“推荐下载”，但没有可验证的完整性或维护归属。
3. 教程聚合页把活跃客户端与停止维护的 Clash for Windows、Clash for Android 并列展示，没有清晰的维护状态边界。
4. 现有 Node 审计没有覆盖教程版本、官方来源、维护状态、故障内链与安全表述。

截至 2026-07-04，官方页面显示：

- Clash Verge Rev 最新稳定版为 v2.5.1。
- FlClash 最新稳定版为 v0.8.93。
- Clash Meta for Android 最新稳定版为 v2.11.30。

版本信息用于建立本次核验基线，不应被写成永久不变的“最新版”。

## 2. 目标与非目标

### 2.1 目标

- 为三款仍活跃的客户端建立一致、可比较、可维护的教程结构。
- 只把官方仓库和官方 Releases 作为软件状态与下载依据。
- 让用户能正确选择操作系统、处理器架构与安装包。
- 把订阅、接管和连接故障导向已有的长尾排查内容。
- 让教程聚合页明确区分当前维护客户端、历史客户端与通用教程。
- 用自动审计保护版本证据、安全边界、内链和响应式意图。

### 2.2 非目标

- 本批不重写 Clash for Windows、Clash for Android、ClashX Pro、Potatso 或 SwitchyOmega 正文。
- 不新增客户端、不更换静态站点架构、不引入构建步骤。
- 不提供或背书第三方下载镜像。
- 不承诺软件绝对安全、长期维护、兼容所有订阅或在所有网络可用。
- 不处理 favicon、社交分享图、Cloudflare 部署、GA4 外链事件或推送部署。

## 3. 方案选择

采用小批量更新三款活跃客户端的方案。

未采用的方案：

- **只替换版本号和下载链接：** 改动小，但会保留教程结构、安全表述和审计缺口。
- **一次重写全部客户端：** 覆盖全面，但证据与浏览器验证范围过大，也不符合外科手术式修改原则。

本方案在搜索价值、证据质量和一次迭代的可验证性之间边界最清楚。

## 4. 页面范围

### 4.1 Clash Verge Rev

路径：`/tutorial/clash-verge/`

定位：Windows、macOS 和 Linux 的桌面主力教程。

必须覆盖：

- 官方名称使用“Clash Verge Rev”，不再把项目简称为 Clash Verge。
- 截至 2026-07-04 核验的稳定版 v2.5.1。
- Windows x64/ARM64、macOS Apple 芯片/Intel 芯片、Linux 常见包格式的选择边界。
- 订阅导入、节点选择、系统代理与 TUN 的最短路径。
- Windows 7 已不在当前官方版本支持范围内，只按官方 Release 说明陈述。

### 4.2 FlClash

路径：`/tutorial/flclash/`

定位：Windows、macOS、Linux 与 Android 的跨平台教程。

必须覆盖：

- 截至 2026-07-04 核验的稳定版 v0.8.93。
- 不把跨平台表述改写成“各平台体验完全一致”。
- 平台与架构选择、订阅导入、启用接管和故障入口。
- 下载入口统一指向官方 Releases。

### 4.3 Clash Meta for Android

路径：`/tutorial/clash-meta-for-android/`

定位：Android 上使用 Mihomo/Clash Meta 配置的教程。

必须覆盖：

- 截至 2026-07-04 核验的稳定版 v2.11.30。
- APK 架构选择；无法判断时优先遵循官方 Release 资产说明，不猜测设备架构。
- Android VPN 权限、系统后台限制与订阅导入。
- 不把 VPN 权限提示描述成故障，也不指导用户关闭系统安全保护。

### 4.4 教程聚合页

路径：`/tutorial/`

聚合页分为三组：

1. **当前维护客户端：** Clash Verge Rev、FlClash、Clash Meta for Android。
2. **历史客户端：** Clash for Windows、Clash for Android 等；明确停止维护或历史定位，不继续作为首选推荐。
3. **通用教程：** 线路选择、美区 Apple ID、浏览器代理等与具体客户端版本无强绑定的内容。

聚合页不替代各教程的版本细节，只提供平台、维护状态和用途分流。

## 5. 统一内容结构

三篇教程使用同一信息架构，但保留平台差异：

1. **编辑核验信息：** 编辑部、官方证据、核验日期。
2. **快速判断：** 适用平台、适合谁、不适合谁。
3. **版本与平台选择：** 当前核验版、操作系统、架构和包格式。
4. **官方下载：** 主入口指向官方 Releases；不提供第三方镜像按钮。
5. **最短配置路径：** 安装、导入订阅、选择节点、启用系统代理或 VPN。
6. **模式说明：** 规则、全局、系统代理与 TUN 的用途边界。
7. **安全与隐私：** 不绕过安全提示，不公开订阅 URL、令牌、账号或未脱敏日志。
8. **故障分流：** 订阅更新失败、已连接但无法上网、频繁断线。
9. **FAQ：** 只回答官方资料和本地步骤能够支持的问题。
10. **官方来源与相关教程。**

共享结构通过既有 `css/main.css` 中的设计变量实现。只添加本批页面实际需要的少量通用类，不建立新的前端体系。

## 6. 下载与版本策略

- 下载按钮指向项目官方 Releases 页面或官方 latest Release 页面。
- 正文展示“截至 2026-07-04 核验：vX.Y.Z”，而不是无日期的“最新版”。
- 不把页面固定成特定安装资产直链，避免新版本发布后按钮继续下载旧包。
- 版本表可以列出官方当前支持的平台与架构，但不复制完整资产清单。
- 用户下载前应在官方 Release 再确认版本、系统和处理器架构。
- 外部官方链接使用 `rel="nofollow noopener"`；这些链接不是商业 CTA，不使用 `sponsored`。

## 7. 证据与表述边界

官方证据：

- `https://github.com/clash-verge-rev/clash-verge-rev/releases/latest`
- `https://github.com/chen08209/FlClash/releases/latest`
- `https://github.com/MetaCubeX/ClashMetaForAndroid`
- Mihomo 官方文档仅用于解释模式、系统代理或 TUN 概念。

必须避免：

- “绝对安全”“安全的”“最受欢迎”“最好用”“完全兼容”等无证据断言。
- 把开源直接等同于安全。
- 把近期发布推断为长期维护保证。
- 建议关闭防火墙、杀毒软件、系统安全保护或绕过来源警告。
- 把第三方镜像称为官方、推荐或可信下载。

可以陈述：

- 官方仓库可公开查看。
- 官方页面在核验日期显示的稳定版与支持平台。
- 用户应核对 Release、文件名、系统架构和项目公告。

## 8. SEO 与结构化数据

- 保留现有 URL，避免丢失已有索引信号。
- 页面标题使用正式项目名、平台和“下载/配置教程”搜索意图。
- 每篇教程提供自洽的 title、description、canonical、Open Graph 与 Twitter 元数据。
- 使用 Article、BreadcrumbList 和 FAQPage JSON-LD。
- Article 的 `dateModified` 为实际实施日期，作者统一为“优质机场推荐编辑部”。
- 三篇教程差异化定位，避免使用完全相同的标题和描述模板。
- 教程聚合页、故障排查页与三篇教程形成可抓取内链。
- Sitemap 只更新本批实际修改的四个 URL。

## 9. 故障处理与隐私

教程只提供可逆、低风险的最短步骤。出现问题时按症状分流：

- timeout、401/403、parse、config validation → `/guide/subscription-update-failed/`
- 客户端显示已连接但应用不通 → `/guide/connected-but-no-internet/`
- 无法连接、频繁断线或无法判断 → `/guide/frequent-disconnections/`

日志、截图和工单内容在分享前必须遮盖订阅 URL、令牌、账号、节点地址、本地 IP 和其他个人信息。

## 10. TDD 与验收

### 10.1 自动审计

先为每一项意图写失败测试，再修改页面：

- 三篇页面具备统一教程结构。
- 页面包含正确的核验版本、日期、平台和官方仓库。
- 不包含旧版本号和 `github.clash.download` 等第三方镜像域名。
- 不包含“安全的”“最受欢迎”“关闭防火墙”等禁止表述。
- 三个故障入口完整且站内链接可解析。
- 教程聚合页正确区分当前维护、历史客户端和通用教程。
- JSON-LD 可解析，canonical 与可见页面一致。
- Sitemap 仅更新本批页面日期。

### 10.2 浏览器验收

桌面与 390px 分别检查：

- 标题、核验信息、下载按钮和步骤层级清楚。
- 版本/平台表格在窄屏只在容器内横向滚动，不造成整页溢出。
- 长链接、文件名和按钮不裁切。
- 聚合页分组清晰，历史客户端不会被误读为首选。
- 三类故障内链能到达正确页面。

### 10.3 完成条件

- 全量 Node 审计通过且没有跳过项。
- `git diff --check` 通过。
- 桌面和 390px 浏览器验收通过。
- 工作区只包含本批授权文件。
- 创建本地提交；未经明确授权不推送、不部署。
