# 极速云邀请页面实施计划

**目标：** 新增极速云机场详情页，并同步机场推荐列表与 Sitemap。

**设计依据：** `docs/superpowers/specs/2026-07-13-jisuyun-invitation-page-design.md`

**架构：** 继续使用纯静态 HTML、共享导航、Giscus 和现有评测 CSS；不新增运行时依赖、页面专属样式或视觉资产。

---

## Task 1：建立页面结构与事实测试（RED）

**修改：** `tests/site-audit.test.mjs`

1. 要求 `jichang/jisuyun/index.html` 具备评测元信息、结论、适合/不适合、特点/限制、三组套餐表、风险、CTA、来源、FAQ 和相关指南。
2. 锁定九档套餐的价格、标称流量、6 倍率折合流量和设备限制。
3. 要求周期套餐只明确月付、季付、半年付、年付；三年折扣冲突必须提示以下单页为准。
4. 要求年付特惠与不限时套餐的无退款规则明确，普通周期套餐不得补写退款结论。
5. 要求线路、解锁、地区、客服、库存和促销信息均有商家归因与时效提醒。
6. 要求 CTA 地址和 `sponsored nofollow noopener` 正确。
7. 要求机场列表卡片与 Sitemap 路由、日期一致。
8. 运行目标测试，确认因页面尚不存在而失败，而非测试语法错误。

## Task 2：新增极速云详情页（GREEN 1）

**新增：** `jichang/jisuyun/index.html`

1. 以 `jichang/quickcloud/index.html` 为结构基线，设置 title、description、canonical、Open Graph、Twitter、Article、BreadcrumbList 和 FAQPage。
2. 写入编辑结论、适合/不适合和可核验特点/限制。
3. 分别建立年付特惠、周期套餐和不限时流量包三张响应式表格。
4. 对中转/直连、解锁、地区覆盖、客服回复、库存、限购和活动统一使用商家归因。
5. 显著说明 6 倍率、无退款范围、普通套餐退款信息缺口、周期冲突和不限时服务持续性风险。
6. 保留现有导航、Giscus、GA4 与共享 CSS；不新增脚本或图片。
7. 运行极速云目标测试直至通过。

## Task 3：同步机场列表与 Sitemap（GREEN 2）

**修改：** `jichang/index.html`、`sitemap.xml`

1. 在机场列表添加极速云卡片，日期为 2026-07-13，摘要使用价格、流量包、倍率和退款事实。
2. 不修改其他机场卡片的内容或独立核验日期。
3. 将机场列表 URL 的 `lastmod` 更新为 2026-07-13。
4. 添加极速云详情 URL，`lastmod` 为 2026-07-13。
5. 运行列表与 Sitemap 目标测试直至通过。

## Task 4：全量自动验证

1. 运行 `node --test tests/site-audit.test.mjs`，要求零失败、零跳过。
2. 解析新页面全部 JSON-LD，确认语法有效且正文、日期和 URL 一致。
3. 使用 `rg` 检查九档套餐、邀请地址、商家归因、退款边界和周期冲突。
4. 运行 `node --check js/nav.js` 与 `git diff --check`。
5. 检查工作区只包含计划允许的文件，并保留用户已有 `.DS_Store` 改动。

## Task 5：桌面与移动浏览器验证

1. 启动本地静态服务器。
2. 在桌面视口检查详情页与机场列表页。
3. 在 390×844 视口确认页面无整体横向滚动，套餐表只在自身容器滚动。
4. 检查首屏、风险提示、CTA、FAQ、导航和 Sitemap 路由。
5. 检查控制台无本站静态资源错误；不打开商业目标、不创建账号或购买套餐。

## Task 6：提交实现

1. 对照设计与计划复核范围。
2. 重新运行完整自动验证并读取输出。
3. 只暂存测试、详情页、机场列表、Sitemap 和本计划，创建实现提交。
4. 不推送、不部署，不修改 GA4 管理端。
