# 网站流量优化 P1：内容信任与评测质量设计

## 背景与目标

P0 已把首页改造成静态内容枢纽，并完成导航、商业链接属性、图片属性、Sitemap 与零依赖审计。本批继续保持纯 Cloudflare Pages 静态架构，以三张代表性机场详情页建立可复用的评测内容约定，再小范围应用到机场聚合页。

目标：

- 用统一的语义区块提升评测的可读性、可比较性和编辑可信度。
- 把商家资料、第三方记录与编辑判断分开，避免把公开资料写成本站亲测。
- 用文字表格替换难维护的旧套餐截图，清理已过期活动。
- 同步收紧正文、FAQ、meta description 与结构化数据中的无证据结论。
- 保留现有暖色编辑型视觉，不引入框架、依赖或构建步骤。

## 用户明确覆盖的原始要求

以下两项与最初 P1 建议不同，以本轮用户决定为准：

1. 页面不显示推广或佣金披露。现有商业 CTA 仍保留 `rel="sponsored nofollow noopener"` 技术标记。
2. 页面不出现“本站未实测”或“待核验”字样，统一使用：

   > 本文仅整理公开资料，实际体验因地区、运营商、设备和时段而异。

商家资料和第三方记录不得改写成本站亲测结论。

## 方案选择

采用“共享语义结构 + 全局 CSS + 静态审计测试”。三张详情页手工使用相同的 HTML 区块与 class，样式集中在 `css/main.css`。不使用 JavaScript 注入正文，也不为三个页面引入模板系统。

该方案比页面内重复样式更容易保持一致，又比运行时组件更适合静态抓取、无脚本访问和当前仓库的维护方式。

## 详情页信息架构

三页按同一顺序组织：

1. 标题与中性摘要。
2. 编辑信息：作者、审核方式、最后核验日期。
3. 一句话结论与资料边界。
4. 适合与不适合人群。
5. 可核验优点与限制/缺点。
6. 套餐文字表格。
7. 性能、线路与解锁资料说明。
8. 购买与使用风险。
9. 官网 CTA。
10. 信息来源与更新时间。

统一编辑信息：

- 作者：优质机场推荐编辑部。
- 审核方式：官网资料与第三方记录交叉核验。
- 最后核验日期：2026-07-02。

## 证据与编辑规则

### 资料层级

1. **商家套餐资料**：用户从当前商家页面抄录并于 2026-07-02 提供，可用于价格、周期、流量、协议、带宽上限、退款和地区限制等文字表格。
2. **第三方记录**：只有同时具备来源、测试日期、网络环境和测试工具时，才引用具体性能数值；否则只作为延伸参考链接。
3. **编辑判断**：适合人群、限制和购买建议必须从前两类明确事实推导，不新增运营年限、稳定率、解锁率或安全性结论。

### 文案规则

- 商家声称的线路类型、流媒体/AI 解锁、客服时效与“不限速”等能力，必须使用“商家资料显示”“商家标注”等归因措辞。
- 实际表现统一提醒会受地区、运营商、设备和时段影响。
- 不设置数字评分、星级或排名。
- 优点只写可核验套餐与功能事实。
- 缺点优先写退款、地区、套餐覆盖、交付和周期约束。
- 删除正文、FAQ、description 和 JSON-LD 中无法支持的确定性结论。

## 视觉设计

继续使用暖白背景、珊瑚色强调、绿色辅助色和衬线标题。新增样式只服务于评测结构：

- 低调的编辑信息条。
- 一句话结论卡。
- 适合/不适合双栏。
- 优点/限制双栏。
- 风险提示块。
- 来源与更新时间区。
- 带表头、斑马层次和清晰数字对齐的套餐表。

移动端双栏折叠为单栏。套餐表放在独立滚动容器中，允许容器内横向滚动，但不得造成整页横向溢出。不新增动画、图标库或交互组件。

## SEO 与结构化数据

- 三页 Article JSON-LD 的作者统一为“优质机场推荐编辑部”。
