# P2 品牌资源与社交分享元数据设计

**日期：** 2026-07-04
**状态：** 已确认，待实施计划
**范围：** favicon、默认社交分享图及四个核心入口页

## 1. 背景

站点没有根目录 `favicon.ico`，浏览器访问页面时会产生已知 404。现有 Open Graph 图片统一指向 300×300 的 `img/clash-300x300.png`，但页面声明 `summary_large_image`，尺寸与横向社交卡片不匹配。部分页面还缺少 `og:image:width`、`og:image:height`、`og:image:alt` 与 `twitter:image`。

## 2. 目标

- 使用现有品牌图形修复 `/favicon.ico` 404，不建立新品牌体系。
- 创建一张 1200×630 的默认横向社交分享图。
- 首批只更新四个核心入口：`/`、`/jichang/`、`/tutorial/`、`/guide/`。
- 让四页 Open Graph 与 Twitter 图片元数据完整、自洽。
- 用自动测试锁定图片尺寸、路径、替代文字和页面范围。

## 3. 非目标

- 本批不批量更新所有文章和机场详情页。
- 不为每篇文章创建独立分享图。
- 不修改 Logo、站点色彩体系、页面正文或导航。
- 不处理 Cloudflare 文档、Vercel/Waline 遗留、GA4 外链事件、推送或部署。

## 4. 视觉方向

### 4.1 Favicon

- 直接取自 `img/logo.svg` 的四向节点标记，不加入文字。
- 保持珊瑚色、鼠尾草绿和深蓝灰的现有品牌颜色。
- 输出根目录 `favicon.ico`，至少包含浏览器常用的小尺寸图标层级。
- 如实现工具允许，同时保留透明背景，避免白色方块。

### 4.2 社交分享图

- 尺寸固定为 1200×630 PNG。
- 暖米色背景，使用现有珊瑚色、鼠尾草绿和深蓝灰。
- 左侧或上方放品牌节点标记，主标题为“优质机场推荐”。
- 副标题为“机场评测 · 客户端教程 · 故障排查”。
- 使用克制的编辑型版式、留白和轻微纸张质感，不使用照片、测速图、节点地图或夸张科技光效。
- 不出现“最好”“高速”“稳定”“安全”等无证据承诺。

资源路径：`/img/social-share-1200x630.png`。

## 5. 页面元数据

四个核心入口页统一使用：

- `og:image=https://www.jichangyun.top/img/social-share-1200x630.png`
- `og:image:width=1200`
- `og:image:height=630`
- 页面语境适配的 `og:image:alt`
- `twitter:card=summary_large_image`
- `twitter:image` 指向同一张横向分享图
- 页面语境适配的 `twitter:image:alt`
- favicon 链接指向 `/favicon.ico`

首页、机场推荐、教程和百科的 alt 可以分别说明页面类型，但不得暗示图片包含具体测速或评测结论。

## 6. 实现策略

- 品牌图应从现有 SVG 资产派生，保证图形与站内 Logo 一致。
- 社交图采用代码可复现的矢量/排版源生成 PNG；不依赖不可控的随机图片生成结果。
- 生成过程只服务本次静态资源，不引入站点构建步骤或运行时依赖。
- 所有页面继续保持纯静态 Cloudflare Pages 架构。

## 7. TDD 与验收

### 7.1 自动审计

先写失败测试，再生成资源和修改元数据：

- `/favicon.ico` 存在、非空且可被静态服务器返回。
- 分享图存在且实际尺寸为 1200×630。
- 四个核心入口页都使用新分享图并声明正确宽高。
- 四页包含 favicon、Open Graph alt、Twitter 图片与 alt。
- 四页不再使用 300×300 图片作为社交分享图。
- 本批之外页面不被测试要求批量迁移。

### 7.2 浏览器验收

- 本地访问 `/favicon.ico` 返回 200，不再出现 favicon 404。
- 四个入口页 head 元数据可读取且路径一致。
- 分享图按原始 1200×630 查看时文字清晰、没有裁切。
- 页面桌面和移动布局不因 head 元数据修改产生回归。

### 7.3 完成条件

- 全量 Node 审计零失败、零跳过。
- `git diff --check` 通过。
- 浏览器资源与页面验收通过。
- 仅提交本批计划内文件。
- 未经明确授权不推送、不部署。
