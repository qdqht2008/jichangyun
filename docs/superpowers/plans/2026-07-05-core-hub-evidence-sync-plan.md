# 网站流量优化：核心入口证据同步实施计划

**目标：** 让首页与机场汇总页只展示已核验的机场摘要和谨慎方法说明，并移除无证据入口。

**设计依据：** `docs/superpowers/specs/2026-07-05-core-hub-evidence-sync-design.md`

**架构：** 继续使用纯静态 HTML、共享样式与现有审计；不新增运行时依赖、数据源或页面。

---

## Task 1：建立修改前基线

**读取：** `index.html`、`jichang/index.html`、`sitemap.xml`、`tests/site-audit.test.mjs`

1. 通读首页 head、首屏、资源列表和更新记录。
2. 通读机场汇总页首屏、方法说明和全部卡片。
3. 确认四条首页机场摘要均可从已核验详情页或汇总卡得到。
4. 运行全量 Node 审计并记录基线。

## Task 2：首页证据口径测试（RED 1）

**修改：** `tests/site-audit.test.mjs`

1. 锁定四条机场链接与已确认摘要。
2. 禁止首页机场资源列表出现旧协议、线路、节点、解锁和“老牌”描述。
3. 禁止 title、description、首屏与入口卡出现稳定保证、免费节点、不跑路和稳定性实测。
4. 要求首页更新记录日期与文字同步为 2026-07-05。
5. 运行目标测试，确认因旧文案失败而非测试语法错误。

## Task 3：机场汇总页证据口径测试（RED 2）

**修改：** `tests/site-audit.test.mjs`

1. 要求副标题聚焦公开套餐的价格、流量和购买限制。
2. 要求购买提示提到退款、设备、地区和长期套餐风险。
3. 禁止“不跑路”“避开 90%”“稳定快速”等保证措辞。
4. 要求方法说明包含卡片核验日期、商家声明边界和统一体验提示。
5. 要求优信云卡片和宣传文字完全退出。
6. 运行目标测试并观察预期失败。

## Task 4：其他卡片与 Sitemap 保护测试（RED 3）

**修改：** `tests/site-audit.test.mjs`

1. 锁定其余十张机场卡片的名称、详情链接与既有核验日期。
2. 要求机场卡片总数从十一张变为十张。
3. 要求首页 Sitemap `lastmod` 为 2026-07-05，机场汇总页保持 2026-07-05。
4. 运行目标测试并观察预期失败。

## Task 5：同步首页（GREEN 1）

2. 替换首屏说明及机场、百科入口卡摘要。
3. 将四条机场链接改为已核验事实摘要。
4. 更新首页变更记录为 2026-07-05。
5. 保持布局、链接数量、教程与指南内容不变。
6. 运行首页目标测试直至通过。

## Task 6：同步机场汇总页与 Sitemap（GREEN 2–3）

4. 运行汇总页、卡片保护和 Sitemap 目标测试直至通过。
