# 网站流量优化 P0 实施计划

**目标：** 在纯静态架构内把首页改造成内容枢纽，修正分类内链、移动导航、商业链接、图片加载属性和 Sitemap，并用可重复执行的审计测试锁定意图。

**架构：** 保持现有 HTML/CSS/JavaScript 结构。公共导航继续由 `js/nav.js` 注入；首页内容使用静态 HTML；新增样式集中在 `css/main.css` 和现有首页局部样式中；测试使用 Node.js 内置模块读取文件进行站点级审计。

**视觉方向：** 暖色编辑型资源目录。保留现有 CSS 变量、衬线标题与暖白背景，通过层级、留白、边框和内容密度增强专业感，不引入新视觉体系。

**技术栈：** HTML5、CSS3、原生 JavaScript、Node.js 内置测试模块、Cloudflare Pages。

---

## Task 1：建立站点审计测试（RED）

**文件：**

- 新增：`tests/site-audit.test.mjs`

**步骤：**

1. 使用 `node:test`、`node:assert/strict`、`node:fs` 和 `node:path` 建立零依赖测试。
2. 分开表达以下业务意图：
   - 分类导航必须把抓取权重导向聚合页。
   - 首页必须提供三个内容簇和重点问题入口。
   - 首页不应为零评论价值加载第三方评论系统。
   - 商业 CTA 必须明确标注推广关系。
   - 正文图片必须避免非必要的首屏加载和布局偏移。
   - Sitemap 必须覆盖公开页面且只声明可信元数据。
   - 根路径站内链接必须指向真实静态文件。
3. 运行 `node --test tests/site-audit.test.mjs`。
4. 确认测试因当前已知缺陷失败，而不是语法错误或测试环境错误。

## Task 2：修正导航并构建首页内容枢纽（GREEN）

**文件：**

- 修改：`js/nav.js`
- 修改：`index.html`
- 修改：`css/main.css`

**步骤：**

1. 把顶栏分类链接改为 `/jichang/`、`/tutorial/`、`/guide/`。
2. 把首页三张主卡片改为对应聚合页。
3. 保留首页 H1，在首屏后添加：
   - 机场选择指南与常见故障排查两个重点入口。
   - 机场推荐、客户端教程、避坑百科三组各四条内容。
   - 真实日期的最近更新区域。
4. 移除首页 Giscus 容器和脚本；保留文章页评论配置。
5. 在现有暖色变量下添加首页内容区样式，不增加 JavaScript 交互。
6. 调整 768px 以下的顶栏字体、内边距、边缘留白和极窄屏滚动行为。
7. 运行站点审计，确认导航、首页内容和 Giscus 相关测试转绿，其余测试仍按预期失败。

## Task 3：规范商业 CTA（GREEN）

**文件：**

- 修改：`jichang/*/index.html` 中包含 `.btn-primary` 外部注册链接的页面

**步骤：**

1. 逐页确认 CTA 指向注册、优惠码或返佣链接。
2. 将其 `rel` 统一为 `sponsored nofollow noopener`。
3. 不改普通文档、项目主页或站内 CTA。
4. 运行站点审计，确认商业链接测试转绿。

## Task 4：补全正文图片加载属性（GREEN）

**文件：**

- 修改：包含正文图片的 `jichang/*/index.html`

**步骤：**

1. 在修改前完整阅读每个目标页面。
2. 使用系统图片元数据工具读取每张源图片的真实宽高。
3. 给正文图片添加 `loading="lazy"`、`decoding="async"`、`width` 和 `height`。
4. 不修改 Logo；不转换图片格式；不改正文、alt 文本或内联视觉样式。
5. 运行站点审计，确认图片性能测试转绿。

## Task 5：重建可信 Sitemap（GREEN）

**文件：**

- 修改：`sitemap.xml`

**步骤：**

1. 从公开 `index.html` 文件生成应覆盖的 URL 清单，排除依赖目录。
2. 补入 `/contactus/`。
3. 移除 `priority` 和 `changefreq`。
4. 本批修改的首页使用 `2026-06-30`；未修改正文的详情页采用各文件最近一次 Git 修改日期。
5. 运行站点审计，确认 Sitemap 覆盖和元数据测试转绿。

## Task 6：全量自动验证

**步骤：**

1. 运行 `node --test tests/site-audit.test.mjs`，要求零失败。
2. 运行 `git diff --check`，要求无空白错误。
3. 使用 `rg` 确认首页没有 Giscus、所有商业 CTA 已标注、所有正文图片具备四项属性。
4. 检查 `git status --short`，确认未跟踪的 `AGENTS.md` 没有进入变更集。

## Task 7：桌面与移动端浏览器验证

**步骤：**

1. 使用 `python3 -m http.server 8080` 启动静态站点。
2. 使用浏览器分别检查桌面宽度与 390×844 移动端。
3. 验证首页区块顺序、所有主要链接、移动导航、横向溢出和页尾位置。
4. 检查浏览器控制台错误。
5. 关闭本地服务器和浏览器会话。

## Task 8：提交实现

**步骤：**

1. 对照设计文档逐项核对验收条件。
2. 查看完整 diff，排除正文改写、无关格式化和 `AGENTS.md`。
3. 再次运行 Task 6 的完整验证命令。
4. 仅暂存计划内文件并创建实现提交；不推送、不部署。
