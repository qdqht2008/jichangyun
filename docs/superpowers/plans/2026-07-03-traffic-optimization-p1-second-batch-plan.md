# 网站流量优化 P1 第二批：机场评测证据门实施计划

**目标：** 在不猜测商家现价和性能的前提下，逐页把飞鸟云、瞬云、红杏云改造成与 P1 第一批一致的静态评测页。

**架构：** 继续手工使用现有评测语义 HTML 与全局 CSS；每页在代码修改前独立通过商家套餐事实门；Node 内置测试逐页锁定结构、事实、归因、CTA 与 SEO 一致性。

**实施策略：** 默认顺序为飞鸟云 → 瞬云 → 红杏云。某页缺少当前商家套餐资料时停在该页的事实门，允许跳到已具备资料的下一页，但不得修改或更新被跳过页面的卡片和 Sitemap 日期。

**技术栈：** HTML5、现有 CSS3、原生 JavaScript 导航、Node.js 内置测试模块、Cloudflare Pages。

**设计依据：** `docs/superpowers/specs/2026-07-03-traffic-optimization-p1-second-batch-design.md`

---

## Task 1：建立逐页事实门工作约定

**文件：**

- 读取：`docs/superpowers/specs/2026-07-03-traffic-optimization-p1-second-batch-design.md`
- 读取：`tests/site-audit.test.mjs`
- 读取：`jichang/feiniaoyun/index.html`
- 读取：`jichang/sy/index.html`
- 读取：`jichang/hongxing/index.html`

**步骤：**

1. 对每页分别建立内存中的事实清单，不新增未经设计批准的数据文件。
2. 商家资料必须来自用户提供的当前套餐页文字或截图，至少能识别套餐名、价格、周期、流量及明确限制。
3. 将商家资料与设计文档列出的第三方来源逐项比较，记录一致项、商家未说明项和冲突项。
4. 冲突时只采用更新且更接近商家原始页面的版本；另一版本仅进入来源说明，不拼接、不取平均。
5. 在开始该页测试前，向用户展示规范化套餐表和限制清单并取得事实确认。
6. 未通过事实确认的页面停止在本 Task；不得为该页增加套餐断言、改正文、改聚合页卡片或更新 Sitemap。

## Task 3：飞鸟云事实门与审计（RED 1）

7. 若引用第三方性能数字，测试同时要求来源、测试日期、网络环境和工具；否则只要求来源链接，不要求具体数值。
